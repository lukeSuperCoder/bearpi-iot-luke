# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

BearPi-IoT Std is a bare-metal STM32L431RCT6 IoT development board project using the STM32 HAL library. MCU: Cortex-M4F @ 80MHz, 256KB Flash, 64KB SRAM. Board features include 8MB external QSPI flash (W25Q64), 1.3" TFT LCD (240x240), SD card slot, and an E53 sensor expansion interface.

## Build System

**Toolchain:** arm-none-eabi-gcc with GNU Make. Flashing via OpenOCD with ST-Link v2.1.

```bash
# Select example application (updates .config)
start menuconfig.exe          # Windows
# or
python menuconfig.py          # cross-platform

# Build
make clean
make -j8

# Flash to board
make download
```

Build outputs go to `build/` as `.elf`, `.hex`, and `.bin` files.

## Configuration System

The project uses a Kconfig-based system. The active example is selected in `.config` (e.g., `CONFIG_A2_BASIC_KEY=y`). The Makefile includes `.config` and `applications/user_demo.mk`, which maps the config flag to the corresponding `applications/<example>/main.c` source file. Only one example compiles at a time.

## Architecture

```
Core/Src/         HAL peripheral init (gpio, usart, spi, i2c, adc, dac, tim, qspi, sdmmc)
Core/Inc/         Headers and pin definitions (main.h, stm32l4xx_hal_conf.h)
Drivers/          STM32 HAL driver library + CMSIS
Hardware/         Board-level drivers:
  LCD/            SPI LCD driver + Chinese font library
  FLASH/          Internal flash operations
  QSPI_FLASH/     External W25Q64 flash driver
  FATFS/          FatFs port for SD card (via SDMMC)
  E53_*/          E53 sensor expansion board drivers (SC1 light, IA1 temp/humidity,
                  SF1 smoke, SC2 6-axis, ST1 GPS, IS1 infrared)
Middlewares/      FatFs file system
applications/     Example applications (A-series: basic peripherals, B-series: E53 sensors)
startup_stm32l431xx.s    Vector table and startup code
STM32L431RCTx_FLASH.ld   Linker script (256KB flash, 48KB+16KB RAM)
```

**Startup flow:** `Reset_Handler` → `SystemInit()` → `main()` → HAL init → clock config → peripheral init → user loop.

All peripheral initialization functions (`MX_GPIO_Init`, `MX_USART2_UART_Init`, etc.) are generated by STM32CubeMX and live in `Core/Src/`. The user application `main.c` is swapped based on the selected example.

## Key Conventions

- Peripheral init code in `Core/Src/` is CubeMX-generated; modify via `.ioc` file if available, not by hand
- User LED is on PC13, user keys are PB2 (KEY1) and PB3 (KEY2)
- USART2 is used for debug printf output (retargeted to `_write` in `usart.c`)
- The project uses `-specs=nano.specs` and `-u _printf_float` for printf float support with minimal libc
- Compiler flags: `-Og` optimization, hard float ABI (`-mfloat-abi=hard -mfpu=fpv4-sp-d16`)
- Linker: 1KB stack (0x400), 512B heap (0x200) — adjust in linker script if needed
- All documentation and comments are in Chinese
